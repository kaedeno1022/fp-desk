# fp-desk 計算ドメイン仕様

シミュレーションエンジンが扱う税・社会保険・年金・金融計算の定義。REQUIREMENTS.md の「将来設計」の詳細仕様にあたる。

**税率・料率・控除額の具体的な数値はこの文書に書かない。** すべて年度キー付きの外部データ（`data/tax-tables/` 配下、形式は実装時に確定）に持ち、投入時に国税庁・総務省・協会けんぽ・各自治体の公表値と突合する。この文書が定義するのは計算の構造・式・境界であって、数値ではない。

## 1. 基本原則

- **課税単位は個人。** 世帯シミュレーションでは夫婦それぞれに独立した税・社保計算を回し、世帯キャッシュフローは合算で表示する。配偶者を「手取り入力」で済ませるモードは作らない
- **年度概念を持つ。** すべての料率テーブルは年度キー付き。「現在の税制を固定」とは、シミュレーション開始時点の最新年度テーブルを全期間に適用するという意味（将来の改正予測はしない）
- **住民税は前年所得課税。** N年の所得に対する住民税はN+1年のキャッシュフローから差し引く
- **端数処理は公式ルールに従う。** 精密計算の検証（公表値との突合）は端数処理が合わないと成立しない。課税所得は1,000円未満切捨て、確定税額は100円未満切捨て、住民税の均等割・所得割の端数等、各制度の公式の丸めルールを料率テーブルと同じ場所に定義として持つ

## 2. 対象とする所得の種類

| 所得種別 | 扱い |
|---|---|
| 給与所得 | 額面年収から給与所得控除を精密計算 |
| 雑所得（公的年金等） | 年金収入から公的年金等控除を精密計算（65歳未満/以上の区分あり） |
| 事業所得 | 所得金額（収入−経費−青色申告特別控除）をユーザーが直接入力。帳簿レベルの計算はしない |
| 退職所得 | 退職金入力時に退職所得控除（勤続年数ベース）・1/2課税・分離課税を精密計算 |
| 譲渡所得（金融資産） | 課税口座の運用益に対する申告分離課税20.315%。取得価額の厳密管理はせず、年次の評価益ベースの簡易計算（§6） |

上記以外（不動産所得・一時所得等）はPhase 1対象外。必要になったら所得金額の直接入力で代替する。

## 3. 現役期の計算

### 3.1 所得税

1. 収入 → 所得金額（給与所得控除等を適用）
2. 所得控除を差し引き課税所得を算出。対象とする所得控除:
   - 基礎控除（所得による逓減を含む）
   - 社会保険料控除（§3.3で計算した実額）
   - 配偶者控除・配偶者特別控除（配偶者の合計所得から判定）
   - 扶養控除（扶養親族の年齢区分: 一般・特定・老人）
   - iDeCo掛金（小規模企業共済等掛金控除）
   - 生命保険料控除・地震保険料控除（ユーザー入力の年額をそのまま控除枠計算に通す）
   - 医療費控除等はPhase 1対象外
3. 累進税率（7段階）で税額算出
4. 税額控除: 住宅ローン控除（§5.2）
5. 復興特別所得税2.1%を加算

※給与所得者の年末調整と確定申告の差異はモデル化しない（年額ベースの計算のみ）。

### 3.2 住民税

- 所得割（市町村民税+道府県民税、一律税率）+ 均等割
- 所得控除は住民税用の控除額テーブルを別途持つ（基礎控除・配偶者控除等は所得税と金額が異なる）
- 調整控除を含む
- 住宅ローン控除の住民税への振替（所得税から引き切れない分）を含む
- N年所得 → N+1年徴収としてキャッシュフローに計上

### 3.3 社会保険料（被用者）

- 健康保険: 協会けんぽ・都道府県別料率。標準報酬月額の等級表を使用。労使折半
- 介護保険第2号被保険者分（40〜64歳）: 健康保険料に上乗せ
- 厚生年金: 標準報酬月額等級表・料率（労使折半）・標準賞与額の上限
- 雇用保険: 業種区分別料率
- 健保組合・共済は対象外（協会けんぽで代用）

### 3.4 自営業者

- 国民年金保険料（定額・年度テーブル）
- 国民健康保険（§4.2と同じ計算を現役期にも適用）

## 4. 退職後の計算

退職後こそライフプランの主戦場であり、現役期と同等の精度で計算する。

### 4.1 年金収入への課税

- 公的年金収入（ねんきん定期便ベースの手入力額）に公的年金等控除を適用して雑所得を算出
- 以降は§3.1・§3.2と同じ流れ（基礎控除・社会保険料控除等を適用）

### 4.2 国民健康保険（退職〜74歳）

- 医療分・後期高齢者支援金分・介護分（40〜64歳のみ）の3区分
- 各区分について所得割（前年所得ベース）+ 均等割（被保険者数）+ 平等割（世帯）を計算し、区分ごとの賦課限度額でキャップ
- **料率は市区町村ごとに異なるため、居住自治体の料率をユーザーが料率テーブルに入力する方式とする**（全国の自治体データは同梱しない。資産割は採用自治体が少ないため対象外）
- 世帯単位で賦課され世帯主が納付するため、世帯合算でキャッシュフローに計上

### 4.3 後期高齢者医療制度（75歳〜）

- 均等割 + 所得割。都道府県広域連合別の料率テーブル
- 賦課限度額・均等割の軽減判定（世帯所得による7割/5割/2割軽減）を含む

### 4.4 介護保険第1号被保険者（65歳〜）

- 市区町村の基準額 × 所得段階別乗率。基準額と段階区分は自治体別のためユーザー入力
- 国保の軽減判定と同様、本人・世帯の所得で段階を判定

## 5. ライフイベントの金融計算

### 5.1 住宅ローン

- 元利均等・元金均等の両返済方式。固定金利のみ（変動金利のシナリオは金利パラメータを変えた別シナリオとして比較する）
- 繰上返済はPhase 2

### 5.2 住宅ローン控除

- 年末ローン残高 × 控除率、住宅区分（新築/中古、省エネ性能）別の借入限度額・控除期間
- 所得税から控除 → 引き切れない分は住民税から控除（上限あり）
- 制度の適用要件（居住年による制度差）は「入居年の制度テーブル」を参照する構造にする

### 5.3 教育費・児童手当・就学支援金

- 進路パターン（公立/私立 × 小中高大）の統計プリセット（文部科学省調査ベース）を年度データとして持ち、ユーザーが子ごとに進路を選択
- 高校は就学支援金（公立11.88万円・私立45.7万円、所得制限なし）を費用から控除する
- 児童手当（所得制限なし・高校生年代まで、3歳未満1.5万円/月・以降1万円/月・第3子以降3万円/月。第3子カウントは22歳以下）を非課税収入として計上する。年度末基準は年齢で近似
- 出産育児一時金は対象外（出産費用側もモデル化しないため相殺前提）

### 5.4 既存の借入（奨学金・自動車ローン等）

- 現在残高・年利・残り返済年数を入力し、開始年から元利均等で完済まで自動返済する
- 住宅ローン控除のような税額控除はない

### 5.5 収入・生活費の時期変化

- 年収は成長率の複利適用に加え、年齢起点の変更リスト（役職定年・転職・再雇用）を指定できる。変更適用後は成長率を使わず指定額で固定する（賃金カーブの頭打ち・減額を表現）
- 基礎生活費は年起点の変更リストで増減できる（子の独立・老後の縮小）。変更額は開始年時点の価格水準で入力し、インフレは開始年からの累積を適用する

## 6. 資産運用・口座区分

- 口座区分: 課税口座 / NISA / iDeCo / 現預金
- 課税口座: 年次リターンに対し20.315%課税（毎年課税の簡易モデル。含み益の繰延は Phase 1 ではモデル化しない）
- NISA: 非課税。生涯投資枠1,800万円・年間投資枠360万円を管理し、枠到達で積立は自動停止する。元本（取得原価）を追跡し、売却時は平均取得単価方式で比例減額する。売却による生涯枠の翌年復活はモデル化しない（Phase 2候補）
- iDeCo: 掛金は全額所得控除（§3.1）。60歳まで引出不可。受取時は一時金なら退職所得控除（他の退職金との勤続年数調整は簡易化して合算）、年金受取なら公的年金等控除。拠出限度額のチェックは行わない（入力側の責任）
- 利回り・インフレ率は資産クラス別・年次別のユーザー指定固定値（確率変動はPhase 2）

### 6.1 積立期と取り崩し期

- 世帯の労働収入（給与・事業）がある間は積立期。労働収入がなくなった年から取り崩し期に自動で切り替わる。取り崩し開始年を明示指定して上書きすることもできる（退職金・現金で当面暮らして運用を温存する戦略等）
- 取り崩し期: 課税口座・NISAへの新規積立を止め、両口座の残高合計 × 取り崩し率（既定4%）を毎年現金化する。売却順は課税口座 → NISA（非課税枠温存の定石）
- 安全網: 現金が不足した年は時期を問わず不足分を課税口座 → NISAの順に自動売却する。警告は全資産を売っても現金がマイナスになる場合のみ出す
- 課税口座は毎年課税の簡易モデルのため、売却時の追加課税は発生しない（整合済み）

### 6.2 インフレの適用範囲

| 項目 | インフレ適用 | 備考 |
|---|---|---|
| 基礎生活費・家賃 | する | 開始年からの累積 |
| 教育費・ライフイベント・借入返済 | しない | 名目固定 |
| 公的年金 | しない | 名目固定。実際はマクロ経済スライドで物価より弱く改定されるため、この扱いは保守側（年金の実質価値を控えめに評価）に倒れる |
| 税率・控除・料率テーブル | しない | 「現在の税制固定」の方針通り |

## 6.3 対象外事項（明示）

以下は意図的にモデル化しない。提案時に口頭補足が必要なものを含む。

- **死亡・遺族年金・必要保障額の算定**: 全員が生存し続ける前提。保障設計はPhase 2候補
- **年金の繰上げ・繰下げの増減率**: 受給開始年齢は変えられるが金額の自動調整（繰上げ-0.4%/月・繰下げ+0.7%/月）はしない。調整後の額をユーザーが入力する
- **退職所得控除の受取間隔調整**: iDeCo一時金と退職金を別年に受け取ると両方フル控除で計算する。実際はiDeCo先受取→退職金の場合は前年以前9年内（令和7年度改正で5年→10年ルール化、2026年以降の受取に適用）、退職金先受取→iDeCoの場合は前年以前19年内の重複期間調整があるため、実際より**有利側**に出る。受取時期が近い提案では注意
- **iDeCo拠出限度額のチェック**: 入力側の責任とする
- **賞与の社保等級判定**: 年収/12を報酬月額とみなす
- **出産育児一時金・育児休業給付**: 対象外

## 7. 検証基準（テスト方針）

「精密」の合格ラインを以下で定義する。

1. **所得税**: 国税庁の確定申告書の手計算例・源泉徴収税額の年額換算と一致すること
2. **住民税**: 主要自治体（居住自治体）の住民税計算例と一致すること
3. **社会保険料**: 協会けんぽ公表の都道府県別保険料額表と等級単位で一致すること
4. **国保・介護**: 居住自治体の公表計算例と一致すること
5. 各制度の境界値（等級の境目、賦課限度額、控除の逓減開始所得、65歳/75歳到達年）をテストケースに含めること

料率テーブル投入時は、出典URL・確認日をテーブルデータ内に記録する。

### 検証状態（2026-07-13時点）

一次情報と突合済み（`verified: true`）: 所得税速算表（公式例と一致）、給与所得控除・基礎控除・配偶者控除/配偶者特別控除・扶養控除（令和7年改正）、生命保険料/地震保険料控除、住民税の均等割・非課税限度額、公的年金等控除、退職所得控除、NISA枠、住宅ローン控除の限度額・控除率、協会けんぽ東京/大阪/愛知・介護2号・厚生年金・雇用保険・国民年金（令和7年度）、児童手当、高校就学支援金。

未突合（`verified: false`のまま）:

- **教育費統計** — 概算プリセット。文科省報告書の詳細表との数値突合は未了（統計値の性質上、概算でも実害は小さい）
- **国保・介護1号・後期高齢者の既定値** — 自治体ごとに異なるため全国版の「正しい値」が存在しない。**居住自治体の公表値での上書きが必須**のプレースホルダ（自治体指定の自動取得は、全国統一のAPI・データベースが存在しないため見送り）

## 8. Phase 1 実装順序（ドメイン部分）

計算エンジンは UI・DB から独立した純関数群として実装し、単体でテスト可能にする。

1. 給与所得者の現役期（所得税・住民税・社保）— §3
2. 住宅ローン・教育費 — §5
3. 資産運用・口座区分 — §6
4. 退職後（年金課税・国保・後期高齢者・介護）— §4
5. 自営業者対応 — §3.4

各段階で§7の突合テストを通してから次へ進む。
