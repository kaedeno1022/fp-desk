# fp-desk 要件定義

## 概要

FP（ファイナンシャルプランナー）業務支援システム。自分専用ツールとして立ち上げ、実際の顧客対応で使ってから他FPへの提供を検討する。

## 想定利用者

自分専用。他FPへの提供・SaaS化はスコープ外（将来検討課題として残すのみ）。

## 開発方針

将来設計（ライフプランシミュレーション）に機能を絞り、Phase 1（決定論的計算）を先に完成させて実務投入する。顧客管理・モンテカルロシミュレーションはPhase 2以降。一度に作り切って需要・使用感の検証が遅れることを避けるため。

## Phase 1（初期実装）

### ログイン

シンプルな認証。Supabase Auth によるメール・パスワード認証。複数テナント対応や権限分離は行わない。

### 将来設計（ライフプランシミュレーション）— 決定論的計算

- 家族情報・収入・支出・資産・負債の入力
- ライフイベント登録（結婚・出産・住宅購入・退職等）
- 所得税・住民税・社会保険料の本格実装（累進課税、基礎控除・給与所得控除・社会保険料控除・配偶者控除等の各種控除を最初から組み込む）
- シミュレーション期間中は現在の税制を固定値として計算する（税制改正の予測は行わない。改正時は税率テーブルを手動更新して再計算）
- 公的年金の見込み額は、ねんきん定期便記載の金額をユーザーが手入力する（日本年金機構の計算式は再現しない）
- 資産運用利回り・インフレ率はPhase 1では単純パラメータ（ユーザー入力の固定値、資産クラス別・年次別に指定可能）として扱い、確率変動は行わない
- キャッシュフロー表・資産推移グラフの自動生成（決定論的な単一シナリオの折れ線グラフ）
- 複数シナリオ比較（パラメータを変えた決定論的シナリオ同士の比較）

## Phase 2（将来拡張）

- 資産運用利回り・インフレ率のモンテカルロシミュレーション化（確率分布に基づく年次リターンのランダムサンプリング、数千回試行、成功確率・パーセンタイル表示、ファンチャート表示への変更を伴う）
- 顧客管理（顧客プロファイル・面談履歴、シミュレーションを顧客ごとに保存・呼び出し）

## スコープ外（将来検討）

- 他FPへの提供・SaaS化（複数テナント対応、権限分離）
- 提案書PDF自動生成
- 電子署名・書類管理連携
- リマインダー・タスク管理

## 技術スタック

Next.js + Supabase（認証・DB・Row Level Security）。

## 制約条件・留意点

- 所得税・住民税・社会保険料の税率テーブルは外部データとして持ち、コードに埋め込まない。税制は毎年改正されるため、テーブル更新だけで対応できる構造にする
- 住民税は前年所得に基づき翌年課税される（所得税とタイミングが1年ズレる）ため、年次計算ロジックで明示的に扱う
- 社会保険料は協会けんぽ・都道府県別料率を対象とし、健保組合の個別料率は対象外とする
- 顧客の資産・個人情報を扱うため、Supabase の Row Level Security によるアクセス制御を必須とする（Phase 2で顧客管理を追加する際に適用）
